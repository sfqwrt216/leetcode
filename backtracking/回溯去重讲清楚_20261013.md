# 回溯去重讲清楚：这些 if 到底什么时候用？

这份说明对应你现有的 `backtracking.md`，重点讲组合、子集、非递减子序列和排列。原笔记保持不变。

你现在容易混，是因为几个条件长得像，变量又都叫 `used`，但它们管的事情不一样。先把下面这句话记住，再往下看例子：

> **沿着一条路径：同一个下标能不能再用？横着换一个分支：换成另一个相同值，会不会得到重复答案？这是两个问题。**

## 1. 先别背 if：分清「下标」和「值」

假设输入是：

```text
下标：  0   1   2
值：    1   2   2
身份：  1  2甲 2乙
```

`2甲` 和 `2乙` 是两个不同位置的元素，只是值一样。甲乙只是讲解用的标签，真正答案里都是数字 `2`。

- `[1, 2甲, 2乙]` 是合法的：两个下标各用了一次，答案是 `[1, 2, 2]`。
- `[1, 2甲]` 和 `[1, 2乙]` 是重复答案：最终都是 `[1, 2]`，只留一个就够了。
- `[1, 2甲, 2甲]` 是重复使用同一个下标：如果题目规定每个元素只能用一次，就不合法。

所以：**「输入中有两个 2，可以一起选」和「同一份答案不能输出两遍」完全可以同时成立。**

你担心去重后丢掉 `[1, 2, 2]`，正是因为把这两件事混到一起了。

## 2. 「同一层」和「同一路径」到底是什么？

对应到代码，比树层、树枝这些术语更直接的说法是：

```python
def backtracking(startIndex):
    for i in range(startIndex, len(nums)):
        # 这个函数调用里的 for：在同一个前缀后面，轮流试下一项
        path.append(nums[i])
        backtracking(i + 1)  # 进入另一次函数调用，在更长的前缀后面选
        path.pop()
```

**同一层：同一次函数调用里的 `for` 轮流试候选。** 此时已经选好的前缀相同，正在决定「下一项选谁」。

**同一路径：一次次递归往下走，元素逐个进入 `path`。**

例如在前缀 `[1]` 后面：

```text
path = [1]，这一次调用的 startIndex = 1
│
├─ 下一项选 2甲 → [1, 2甲]
│                  └─ 进入下一次调用，还可以选 2乙 → [1, 2甲, 2乙]
│
└─ 下一项选 2乙 → [1, 2乙]  ← 和上面的 [1, 2甲] 是重复的
```

横着的两个分支「下一项选 2甲 / 2乙」要去重。竖着的「已经选了 2甲，再选 2乙」要保留。

这里的「同一层」强调**同一个前缀下的候选**，不是把所有深度相同的节点放在一起去重。

## 3. 先判断题目，再选择条件

每道题先问这四个问题：

1. **顺序算不算不同答案？** `[1, 2]` 和 `[2, 1]` 算不同，就是排列类；算同一个，就是组合、子集这类选择问题。
2. **同一个下标能不能重复选？** 决定递归传 `i`、`i + 1`，或者用下标标记。
3. **输入有没有重复值，输出是否要求不重复？** 决定是否需要同层去重。
4. **能不能排序？** 如果必须保留原数组的先后顺序，就不能通过排序来让重复值挨在一起。

下面是你目前这几道题的选择表。它针对这里展示的 `for` 循环回溯模板，不是说所有解法都只能这样写。

| 题目 | 如何控制下标使用 | 如何避免相同答案 |
| --- | --- | --- |
| 77 组合、78 子集：候选无重复 | `startIndex`，下一层传 `i + 1` | 无须额外同层去重 |
| 39 组合总和：候选无重复，可反复选 | `startIndex`，下一层传 `i` | 无须额外同层去重 |
| 40 组合总和 II、90 子集 II：有重复值 | `startIndex`，下一层传 `i + 1` | 排序后，`i > startIndex and nums[i] == nums[i - 1]` |
| 491 非递减子序列：保留原顺序 | `startIndex`，下一层传 `i + 1` | 每次调用新建 `used_this_level = set()`，按值去重 |
| 46 全排列：值互不相同 | 每层从 `0` 遍历，用 `used_index[i]` 标记当前路径的下标 | 无须额外同层去重 |
| 47 全排列 II：有重复值 | 每层从 `0` 遍历，用 `used_index[i]` 标记当前路径的下标 | 排序后，再加相邻重复判断和 `not used_index[i - 1]` |

**组合和子集主要差在什么时候收答案。** 组合通常满足数量、总和等条件才收；子集通常每进入一次递归就收当前 `path`。候选里有重复值时，它们可以使用同一种同层去重方式。

## 4. 组合、子集：为什么是 `i > startIndex`？

你笔记里 40、90 用的是：

```python
nums.sort()

for i in range(startIndex, len(nums)):
    if i > startIndex and nums[i] == nums[i - 1]:
        continue
```

把条件翻译成人话：

> **如果我不是这次 for 的第一个候选，而且我的值和紧挨着的前一个候选一样，就跳过我。这个前缀后面已经试过这种值了。**

`startIndex` 每次递归可能不同，它是**本次调用**的循环起点。不是固定的 `0`。

### 用 `[1, 2甲, 2乙]` 逐步看

当 `path = [1]`，本次 `startIndex = 1`：

| 当前候选 | 条件 | 动作 |
| --- | --- | --- |
| `i = 1`，选 2甲 | `1 > 1` 为假 | 允许选，进入 `[1, 2甲]` 的递归 |
| 从递归返回后，`i = 2`，试 2乙 | `2 > 1` 为真，且值相同 | 跳过，避免再生成 `[1, 2]` 这一分支 |

但在 `[1, 2甲]` 的递归里，下一层的 `startIndex = 2`：

```text
i = 2
startIndex = 2
i > startIndex 是假
因此允许选 2乙，得到 [1, 2, 2]
```

**这就是 `i > startIndex` 的作用：前一个重复元素如果在本次循环范围内，就跳过；如果已经在上一层选进路径里，就允许继续选另一个。**

### 为什么不能随手换成 `i > 0`？

```python
if i > 0 and nums[i] == nums[i - 1]:
    continue
```

在上面的下一层，`i = 2` 时这个条件成立，就把 2乙跳过了，合法的 `[1, 2, 2]` 消失。

它只知道数组里「前面有一个相同值」，不知道那个值已经在当前路径里。**所以单独的这条判断，不适合这里的子集 II、组合总和 II，也不适合全排列 II。**

`i > 0` 还保证了 `i - 1` 是前一个下标。Python 中 `nums[-1]` 会取最后一个元素，不会因为负下标自动报错；不加边界条件可能出现错误比较。

### 子集 II 的完整模板

```python
def subsets_with_dup(nums):
    nums = sorted(nums)
    result, path = [], []

    def dfs(startIndex):
        result.append(path[:])  # 当前路径就是一个子集，包含空集

        for i in range(startIndex, len(nums)):
            if i > startIndex and nums[i] == nums[i - 1]:
                continue
            path.append(nums[i])
            dfs(i + 1)
            path.pop()

    dfs(0)
    return result


print(subsets_with_dup([1, 2, 2]))
# [[], [1], [1, 2], [1, 2, 2], [2], [2, 2]]
```

### 组合总和 II：同样去重，换一个收答案的条件

```python
def combination_sum2(nums, target):
    # 此模板针对题目中的正整数候选
    nums = sorted(nums)
    result, path = [], []

    def dfs(startIndex, remaining):
        if remaining == 0:
            result.append(path[:])
            return

        for i in range(startIndex, len(nums)):
            if i > startIndex and nums[i] == nums[i - 1]:
                continue
            if nums[i] > remaining:
                break  # 已排序，后面的正整数也不可能满足
            path.append(nums[i])
            dfs(i + 1, remaining - nums[i])
            path.pop()

    dfs(0, target)
    return result


print(combination_sum2([1, 1, 1, 2, 3], 6))
# [[1, 1, 1, 3], [1, 2, 3]]
```

你笔记里担心的 `1113` 和 `123` 都保留了。相同的 1 可以逐层选入路径，只是不能在同一个前缀下反复从不同的 1 开始生成同一批答案。

## 5. 排列：为什么多出 `and not self.used[i - 1]`？

排列中 `[1, 2]` 和 `[2, 1]` 是不同的答案。所以选了下标 1 后，下一层仍可能需要选下标 0。

因此排列模板每层都从 `0` 开始遍历，不能靠递归传 `i + 1` 来限制候选；否则顺序一直向右，很多排列就没了。

### 第一条判断：同一个下标不能在当前路径里用两次

```python
if self.used[i]:
    continue
```

这里 `self.used` 是布尔数组，含义是：

```text
self.used[i] = True  → 下标 i 目前在 path 中
self.used[i] = False → 下标 i 目前不在 path 中
```

它不是「这个值曾经试过」，也不是「整个算法永远不能再用这个下标」。递归回来后必须恢复为 `False`，其他分支还要用。

### 第二条判断：相同值按下标先后顺序选

```python
if i > 0 and nums[i] == nums[i - 1] and not self.used[i - 1]:
    continue
```

前提：已排序。把它翻译成人话：

> **当前值和前一个值一样时，只有前一个下标已经在路径里，才允许选当前下标。**

用 `[1甲, 1乙, 2]` 来看，这条规则要求一条路径中先用 1甲，再用 1乙。答案不区分甲乙，所以规定一个统一的选取顺序，就不用生成它们交换身份的重复答案。

### 在根节点试 1乙：应该跳过

```text
path = []
used = [False, False, False]
当前 i = 1，候选是 1乙

i > 0                         → True
nums[1] == nums[0]             → True
not used[0]                   → True

跳过：这个位置让 1甲开头就够了。
```

### 已经选了 1甲，再试 1乙：应该允许

```text
path = [1甲]
used = [True, False, False]
当前 i = 1，候选是 1乙

i > 0                         → True
nums[1] == nums[0]             → True
not used[0]                   → False

不跳过：允许得到 [1甲, 1乙, 2]，真正答案是 [1, 1, 2]。
```

### 完整分支看起来是这样

```text
[]
├─ 1甲
│  ├─ 1乙 → 2 → [1, 1, 2]
│  └─ 2 → 1乙 → [1, 2, 1]
├─ 1乙 → 跳过，1甲不在路径里
└─ 2
   ├─ 1甲 → 1乙 → [2, 1, 1]
   └─ 1乙 → 跳过，1甲不在路径里
```

**`not used[i - 1]` 为真，准确含义只有「前一个下标当前不在路径里」。** 在这个从左到右遍历的模板中，优先让前一个相同值代表这个选择，就能去掉重复分支。不要把 `False` 背成「本层已经访问过」：布尔数组本身并没有记录本层的访问历史。

### 全排列 II 的完整模板

```python
def permute_unique(nums):
    nums = sorted(nums)
    result, path = [], []
    used_index = [False] * len(nums)

    def dfs():
        if len(path) == len(nums):
            result.append(path[:])
            return

        for i in range(len(nums)):
            if used_index[i]:  # 当前路径中，同一个下标不能再用
                continue
            if i > 0 and nums[i] == nums[i - 1] and not used_index[i - 1]:
                continue  # 相同值，先用前面的下标

            used_index[i] = True
            path.append(nums[i])
            dfs()
            path.pop()
            used_index[i] = False

    dfs()
    return result


print(permute_unique([1, 1, 2]))
# [[1, 1, 2], [1, 2, 1], [2, 1, 1]]
```

如果题目是 46，输入值互不相同，保留下标使用标记即可，无须排序，也无须相邻重复判断。

有些资料会给出不同的排列去重写法；先把这里这个「相同值先用前面的下标」模板学稳，不要只替换条件中的一个词而忽略整套遍历规则。

## 6. `used.add(nums[i])` 为什么有时撤销，有时不撤销？

**只看到 `.add()`，无法判断它管什么。要一起看：集合在哪里创建，存的是值还是下标，递归后有没有删除。**

### A. 非递减子序列：每次调用创建一个「本层值集合」

你的 491 题是这种：

```python
def dfs(startIndex):
    used_this_level = set()  # 每次调用都会新建；必须放在 for 外面

    for i in range(startIndex, len(nums)):
        if nums[i] in used_this_level:
            continue
        if path and nums[i] < path[-1]:
            continue

        used_this_level.add(nums[i])
        path.append(nums[i])
        dfs(i + 1)
        path.pop()
        # 不删除 used_this_level 里的 nums[i]
```

它记的是：**在当前这个前缀后面，哪些值已经作为下一项探索过了。**

比如 `[4, 7甲, 6, 7乙]`，当 `path = [4]` 时：

- 先选 7甲，已经得到 `[4, 7]`，并探索了这个分支的后续。
- 回到 `[4]`，以后轮到 7乙，值 7 已经在本层集合里，跳过重复的 `[4, 7]` 分支。
- 在 `[4, 7甲]` 的递归中，有一个全新的空集合，所以可以继续选 7乙，保留 `[4, 7, 7]`。

为什么保留靠前的同值候选就够了？它后面能选的下标包含靠后的同值候选后面能选的下标，因此后者生成的值序列，前者也能生成。

**本层集合不撤销，是为了让这个 for 后面的候选记住：这个值已经试过了。** 如果递归回来就删除，轮到另一个 7 时又忘了前面的 7，重复答案就回来了。

也不能把 `set()` 放在 `for` 里面：每轮都清空，它就记不住之前的候选。

### 为什么 491 不能直接套排序后的相邻判断？

非递减子序列必须遵守**原数组中的下标先后顺序**。

```text
原数组：[4, 7, 6]
[4, 6] 是合法子序列
[6, 7] 不是合法子序列，因为原数组里 6 在 7 后面

如果排序成 [4, 6, 7]，就会错误生成 [6, 7]
```

不能排序，重复值就可能不相邻。比如上面的两个 7 中间隔着 6，`nums[i] == nums[i - 1]` 检测不到它们；本层集合可以。

非递减条件也要和 `path[-1]` 比，而不是 `nums[i - 1]`：数组中的前一项未必被你选中了。

```python
def find_subsequences(nums):
    result, path = [], []

    def dfs(startIndex):
        if len(path) >= 2:
            result.append(path[:])

        used_this_level = set()
        for i in range(startIndex, len(nums)):
            if nums[i] in used_this_level:
                continue
            if path and nums[i] < path[-1]:
                continue
            used_this_level.add(nums[i])
            path.append(nums[i])
            dfs(i + 1)
            path.pop()

    dfs(0)
    return result


print(find_subsequences([4, 7, 6, 7]))
# [[4, 7], [4, 7, 7], [4, 6], [4, 6, 7], [7, 7], [6, 7]]
```

### B. 全排列且值互不相同：整个搜索共享「当前路径值集合」

你 46 题的另一版代码是这种：

```python
self.used = set()  # 在入口初始化一次，各次递归共同使用

# 递归中的选择流程：
if nums[i] in self.used:
    continue
self.used.add(nums[i])
self.path.append(nums[i])
self.backtracking(nums)
self.path.pop()
self.used.remove(nums[i])  # 必须撤销，让其他分支可以再次使用
```

它记的是：**当前 path 中有哪些值。** 当输入没有重复值时，值能唯一对应下标，所以按值标记也可以。

但如果输入是 `[1甲, 1乙, 2]`，选了 1甲后，集合里已经有 `1`，就会把 1乙也挡住。这样永远拼不出合法的 `[1, 1, 2]`。

因此：**用「值集合」防止排列中重复使用元素，仅适用于输入值互不相同的情况。** 有重复值时，改用下标布尔数组，或存下标的集合。不是 set 本身不能用于重复值排列，而是「按值标记当前路径」区分不了两个 1。

### 两种集合放在一起比较

| 比较项 | 本层值集合：491 | 当前路径标记：46、47 |
| --- | --- | --- |
| 创建位置 | 每次递归调用里，`for` 前 | 搜索入口初始化一次 |
| 记什么 | 当前前缀后，已经探索过的候选值 | 当前路径正在使用的元素 |
| 不同递归调用是否共享 | 不共享，每次调用有自己的集合 | 共享，随选择和撤销更新 |
| 回溯后是否撤销 | 不撤销本层集合 | 必须撤销路径标记 |
| 按值还是下标 | 按值，因为要合并相同值分支 | 优先按下标；值互不同时也能按值 |

建议写代码时直接叫 `used_this_level` 和 `used_index`。不要所有东西都叫 `used`，很容易把含义记串。

## 7. 把你问的四种写法逐个对上

| 写法 | 在这里的用途 | 使用前提 / 注意点 |
| --- | --- | --- |
| `i > 0 and nums[i] == nums[i - 1]` | 单独表示当前值与前一项相同 | 不能单独作为这些重复值题目的去重条件，会误删合法的连续选取 |
| `i > startIndex and nums[i] == nums[i - 1]` | 组合、子集的同层去重 | 先排序；`for` 从本次 `startIndex` 开始 |
| `i > 0 and nums[i] == nums[i - 1] and not used_index[i - 1]` | 全排列 II 的同层去重 | 先排序；还要有 `if used_index[i]` 防止路径重用下标 |
| `used_this_level.add(nums[i])` | 记录本层已经探索过的值 | 每次递归新建集合；配合成员判断；本层不撤销 |
| `self.used.add(nums[i])` | 也可能是记录当前路径中的值 | 若按 46 模板使用，输入值必须互不相同，回溯时删除 |

注意：**`.add()` 是记录动作，`if nums[i] in ...: continue` 才是拦住重复选择的判断。** 不能只加记录，不做检查。

如果愿意，40、90 也可以用本层值集合去重；47 也可以用「路径下标标记 + 本层值集合」。这些是可替代方案，不需要同时把所有去重方式叠起来。先熟悉上面的标准模板即可。

## 8. 再拆开一个容易混的点：`i` / `i + 1` 与去重各管什么？

```python
dfs(i + 1)  # 下一层只能看后面的下标：当前下标不再选
dfs(i)      # 下一层仍然可以选当前下标：允许重复使用
```

- 40、90、491 传 `i + 1`：一个下标只能选一次，但不同下标的相同值可以逐层选。
- 39 传 `i`：允许一个候选值反复使用，例如一个 `2` 可以凑出 `[2, 2, 3]`。
- 46、47 每层遍历全部下标：用路径标记挡住已经使用的下标。

**先决定能不能重用下标，再决定怎样去掉重复答案。** 不要看到两个相同数字，就靠把 `i` 改成 `i + 1` 来解决全部重复问题。

`startIndex` 本身还能保证选择下标一直向右，避免先选 1 再选 2、又先选 2 再选 1。输入有重复值时，仍需额外合并「不同下标、相同值」产生的重复答案。

## 9. 三个小自测：能说清理由才算懂

### 题一：子集 II，输入 `[1, 2, 2]`

已经选了 `[1, 2甲]`，下一次递归 `startIndex = 2`，当前 `i = 2`。要不要跳过 2乙？

<details>
<summary>看答案</summary>

不要。`i > startIndex` 为假，当前候选是本次调用的第一个选择。它会生成合法子集 `[1, 2, 2]`。

但回到 `path = [1]`、`startIndex = 1` 的调用，再试 `i = 2` 时，要跳过。这里是在同一个前缀后换了一个值相同的候选，会重复生成 `[1, 2]` 分支。

</details>

### 题二：全排列 II，输入 `[1, 1, 2]`

根节点能不能直接选 1乙？已经选了 1甲后，能不能选 1乙？

<details>
<summary>看答案</summary>

根节点不选：`used_index[0]` 为假，`not used_index[0]` 为真，跳过 1乙。

选了 1甲后可以选：`used_index[0]` 为真，`not used_index[0]` 为假，不触发去重条件。

统一让甲先于乙进入路径，就只生成一份相同值的排列。

</details>

### 题三：491，输入 `[4, 7, 6, 7]`

探索完 `[4, 7甲]` 回到 `[4]`，本层集合里的 7 要不要删除？如果不删除，会不会丢掉 `[4, 7, 7]`？

<details>
<summary>看答案</summary>

不删除，后面那个 7 不用在 `[4]` 后面再开一个重复分支。

不会丢掉 `[4, 7, 7]`：探索 `[4, 7甲]` 时，递归调用拥有自己的新集合，可以选后面的 7乙。

</details>

## 10. 下次写题时，按这个顺序落笔

1. 写出候选范围：从 `startIndex` 开始，还是每次从 `0` 开始？
2. 写出元素使用规则：递归传 `i + 1`、传 `i`，还是使用路径下标标记？
3. 有重复值且答案要求唯一时，再加同层去重：可排序的组合/子集用 `i > startIndex`；排列用下标标记配合相邻条件；保留原序的子序列用本层集合。
4. 最后写收答案的条件、选择、递归、撤销。

遇到看不懂的条件，就拿两个相同值标成甲乙，问：**我现在是在同一个前缀后，换另一个相同值开分支，还是已经选了甲，要继续选乙？**

把这一点分清，这些条件就有理由了，不需要按题号硬背。
